# Forest Survivor

A medieval, Diablo-flavoured survivors-like for the browser. Pick a hero, auto-attack your way through ever-growing hordes, level up into evolved weapons, **survive** on five maps, each opening the next (the Sunscorch's dunes and the snows of the Frostfell by day, then by night the Bloomvale in flower, the Darkwood and the fires of the Abyss), **delve three dungeon floors** to slay the Lord of Cinders, and finally see how long you last in the **endless Ranked night**.

Everything is hand-made in code: pixel-art sprites authored as palette strings, procedurally painted trees and dungeon tiles, a dynamic light map and synthesized sound effects. The menus' frames, buttons and title font are the exception: Foozle's Lucifer RPG UI and Kenney's Fantasy UI Borders (both CC0) and the Pixtura12 and Jacquard blackletters by eishiya and Sarah Cadigan-Fried (SIL OFL), baked into `public/assets/ui/` by `tools/bake-ui.mjs` and `tools/bake-fonts.mjs` (credits in `public/assets/ui/CREDITS.md`). The weapon effect sprites in `public/assets/art/vfx.js` are baked by `tools/vfx/` from Sprite Fusion's pixel-art VFX (MIT, Copyright (c) 2026 Hugo Duprez; credits in `public/assets/art/VFX-CREDITS.md`). Music: the original dark-fantasy score **Thorns and Iron** pairs galloping metal guitars, driving drums and minor-key melodies with a folk whistle. Three combat loops cover the forest, crypt and bosses, with matching title and aftermath cues. Composition source, MIDI and audio measurements are in `tools/music/combat/`; credits are in `public/audio/music/CREDITS.md`. The files listed in `public/audio/music/tracks.json` play as exact bar-length Ogg loops. There are no runtime dependencies.

## Run it

```bash
npm start          # http://localhost:3000
npm run dev        # same, with developer mode open and auto-restart
npm test           # everything in test/
npm run bots       # bots play-test the game headlessly (see Bot play-testing)
```

Requires Node 18+ (the tests, Node 21+). Set `PORT` to change the port.

## Publish it on GitHub Pages

Every push to `main` that changes `public/` publishes the game once `npm test` passes (`.github/workflows/pages.yml`). Only `public/` goes out: not the server, the tools or the Sprite Lab.

One-time setup, in the repository's **Settings → Pages**:

1. **Source:** GitHub Actions. Then push, or run **Publish the game** from the Actions tab.
2. **Custom domain:** enter it, and add records at the domain's DNS:
   - a subdomain such as `play.example.com`: a `CNAME` to `bonegor.github.io`
   - the bare `example.com`: `A` records to `185.199.108.153`, `185.199.109.153`, `185.199.110.153` and `185.199.111.153`, and `www` as a `CNAME` to `bonegor.github.io`.
3. **Enforce HTTPS** once GitHub has issued the certificate.
4. **Verify the domain** in your account's own Settings → Pages, so no one else can attach it to their site.

There's no game server on Pages (its `/api` calls get a 404), so:

- **The save is in the browser's localStorage** (see Saving). A player can read and edit their own with the browser's tools. That reaches no one else, since players share nothing.
- **Developer mode is off.** The panel opens only on this machine (localhost). The debug address (below) works there, though, and its developer panel with it, on the debug game's own save.
- **The page carries the server's content security policy** in a meta tag, all of it but `frame-ancestors`, which a meta tag can't set.
- **Saves belong to the domain.** A move to another domain, or to a game server, starts every player afresh.

## Release for itch.io

`node tools/build-itch.mjs` (or `npm run itch`) builds the game for itch.io into `dist/itch/` and zips it to `dist/forest-survivor-itch.zip`, to upload as an HTML game played in the browser (embed 960×540, with the fullscreen button; not started on page load, so the click that starts it lets the music play). The repository stays the one game: the build copies it and switches its copy of `public/js/engine/build.js` to `RELEASE`, which never asks for a game server, keeps no debug address and no developer panel. Only what a player needs goes in: the page, the game's code without `js/dev/` and `js/bots/`, `assets/`, and the music `tracks.json` plays with its credits and licences (about 31 MB, against some 250 MB in `public/`). The build fails if a module the game imports is missing from the copy, or if it is past itch.io's limits (1,000 files, 500 MB) (`test/itch.test.js`).

The save there is in localStorage: itch.io frames the game from another site (itch.zone), where browsers block or partition cookies. The Pages workflow also publishes the same build at an unlisted address on the site (the owner's link list has it), to play what ships before it is uploaded; it shares the site's save with the game itself.

## How to play

| Action | Keyboard | Gamepad | Touch |
| --- | --- | --- | --- |
| Move | WASD / arrows | left stick / d-pad | drag anywhere |
| Ultimate (when the fury orb is full) | Space / E / Q | X / triggers | tap the fury orb |
| Strike (in crypts) | X / Shift | LB / RB | tap a second finger |
| Pause | Esc / P | Start | ⏸ button |
| Dungeon or crypt map | Tab / M | Back | — |
| Pick a level-up card | 1–5, arrows + Enter, click | d-pad + A | tap |
| Reroll level-up | R | Y | button |
| Banish a level-up card | B (the card in focus), or BANISH then the card | left-stick press (arms it, again cancels), then A on the card | hold the card, or BANISH then tap it |
| Always take this filler (build maxed) | Shift + 1–5, or tick ALWAYS under the card | d-pad down to ALWAYS + A | tap ALWAYS |

Weapons fire automatically, except in the crypts (below). Collect soul gems to level up; every level offers a choice of new weapons (the hero's own signature and those shared by all, below), weapon upgrades or relics. The levels themselves give the hero nothing (the owner's, 21 October 2026: "Levelups do not make hero stronger"; `levelBonus` in `public/js/game/player.js` stays at nought): only the cards make him stronger, so the level-up screen just says "LEVEL n · choose one". It pops up mid-fight, so for its first 0.75 s its cards stand greyed: the focus moves (arrows, a pad, the mouse, a click or tap, a card's number) but nothing is taken, and a press then is dropped, never kept for later; Space, the ultimate's key, never takes a card. Levels gained at once (a big soul gem) come one screen after another: the first is stamped ×3 beside LEVEL UP!, the next 2 of 3 and 3 of 3 (levels the run's ALWAYS takes unseen are not counted), and the experience bar at the top runs to its end, flashes and starts again for each. Each card says NEW WEAPON or NEW RELIC (FIRST FIND the first time this browser is offered one a milestone opened), or the level it brings, with pips for the levels so far. A run has as many **rerolls** and **banishes** as the Armory's Insight and Exile ranks give (none without them since 21 October 2026; a save from before then was given two ranks of each): REROLL draws all new cards; BANISH takes the card in focus off the screen and its weapon or relic out of the run for good, never offered again on a level-up or in a chest (one the hero already holds stays, at the level it has), and a card drawn anew takes its place. A filler can't be banished, and no level can be skipped. When fewer upgrades are left than a level-up offers, fillers fill the rest, three at most: a stacking **Blessing of Valor** (+5% might, +2% health), **Roast Chicken** (heals 35%, more for a hero who heals more: the Paladin's 52%) and a **Purse of Gold** that grows with the night and your greed (30 gold at dusk, 72 at minute 10, counted with the gold you find). Once the whole build is maxed a level-up shows every filler (never a copy of one, and no reroll or banish to spend): those three and the stacking **Blessing of Haste** (3% off every cooldown, down to the floor every cooldown has, 0.35) and **Blessing of Reach** (+5% area, twenty times at most), the owner's (27 October 2026): one Blessing for ever made every level the same (`FILLERS` and `BLESSING` in `public/js/data/passives.js`). A Blessing that would give nothing more is not offered, and an ALWAYS ticked on it turns to Valor. Each has an **ALWAYS** toggle under it (or Shift + its number): take a card with ALWAYS ticked and every level-up for the rest of the run takes it with no screen and no pause, a line over the hero saying what it gave ("Blessing ×17", "Haste ×4", "+35% health", "+41 gold"). The pause menu shows the choice ("Level-ups: always Gold") with **ASK AGAIN** to undo it; it lasts the run, not between runs. Chests draw from the same upgrades as the level-up cards, but only levels of the weapons and relics you already have: a chest never gives anything new while one of them can still grow, and only once all are at their top does it draw a new weapon or relic (while a slot is free), so it never comes back with gold alone while anything is left to grow; with the build maxed, each of its draws is your ALWAYS choice, else a Blessing.

The **fury orb** (bottom right) fills toward the ultimate, which fires only when it is full and empties it (`FURY` in `public/js/game/player.js`). Kills fill it, each worth less the faster you are killing: a lone kill 0.75%, half that at 40 kills a minute, so the horde gives no more than about 30% a minute however many fall. Blows on a boss, a crypt lord or a champion fill it by the share of its health they take (a boss's whole health is a full orb, a lord's 60%, a champion's 30%; the ultimate's own blows give nothing), and killing one adds 35%, 25% or 8%. Your own wounds fill it too, a quarter of your health lost a fifth of the orb. And a **fury orb** gives 40%. So it comes from fighting the big ones, from trouble and from what you break, not from the horde alone.

**Quit Run** in the pause menu ends the run there and then, and you keep the gold you found. A run is never saved to come back to: progress (gold, wins, records, unlocks, the gear worn) is saved only when the run ends, by death, by Quit Run, or by victory and back to the menu. Close the game mid-run and that run is gone, with nothing of it kept.

### The road to the Sunscorch

A new player's **Begin Adventure** starts with the Knight at a daylight camp. A caravan road
leads east across the desert through a few gentle bends: roughly 40 seconds of walking to the
Sunscorch, the first of the Survival maps, with room to explore above and below it. It is the
Sunscorch by day (`DayForest` in `public/js/game/prologue.js`): sand in the sun, saguaros,
joshua trees and scrub, and a dozen date palms along the road. Six small encounters send 16
rats along the way. Saguaros behind camp, and palms by the road's end, close the western
boundary. A few rats guard the road, dropping gold and occasional healing potions; there is no
experience or levelling. After eight seconds without progress along the road, a gentle arrow
and **Follow the path** point the player back toward it.

At the destination a brief story transition ("By midday, Aldric reached the Sunscorch. Something
stirred beneath the sand.") starts the Knight's first night on Normal, in the Sunscorch, at
level 1 and full health. Collected gold goes into that night and is saved with its results.
**Skip Intro** also starts the night. Completion or skipping is remembered in settings, and with
it the Sunscorch as the trial screen's map; existing players go straight to the usual hero
selection. **Replay Intro** on the main menu visits the road again without changing progress or
awarding gold. Keyboard, gamepad and touch movement all work, and the pause button stops the
journey and its reminder.

### Modes

- **Survival — 15 minutes.** Endless land, night falls darker, three bosses arrive on a schedule. Survive until dawn to win. It is played on five maps, each opened by a night won on the one before it (below).
- **Dungeon Run — 3 floors.** Each floor's guardian sleeps iced over behind a seal until you've slain enough foes and spent long enough on the floor; the blows you land on it thaw the seal too (it loses no health), breaking it in as little as half the time. Kill it, take the stairs, and defeat the Demon Lord on floor 3. Your build carries over between floors.
- **Ranked — endless.** No dawn. The night keeps getting deadlier, the four lords return in rotation every 4½ minutes, and past the half-hour a blood moon rises. Your score is how long you last, kept as a personal best per hero with a rank title (Peasant, Squire, Knight, Champion, Paladin, Warlord, Hero at 30 minutes, Legend at 40, Mythic at 50, Immortal at an hour). Its records are personal bests, not a shared leaderboard. The first time it is chosen, a note says it is always played on Elite, and the next goal asks for a night won on Elite before it.

The Darkwood (Survival and Ranked) is one endless forest, the same in every run; the Bloomvale is laid out the same way, from a seed of its own, while the Sunscorch, the Frostfell and the Abyss lie on ground of their own (below). In the Darkwood you start on a crossroads with four roads out to the four corners; each runs about 30 seconds of walking, mostly straight with the odd bend, to another crossroads with a wayside shrine, and on from there in every direction. The four roads out of any crossroads lead to four different shrines. Groves, meadows, pine and cursed woods, and landmarks down footpaths (stone circles, ruins, graveyards, woodcutters' camps) fill the woods between. Nothing is stored: every patch of forest is worked out from a fixed seed as you reach it (`public/js/game/darkwood.js`; `node tools/mapgen/endless.mjs` draws previews of it, and with `--biome=desert`, `frozen`, `meadow` or `hell` of another map, in its look and on its own ground where it has one, `--run=<seed>` or `--variant=lava|void` choosing the Abyss's lava or void).

Every second crossroads has a **crypt** beside its shrine, so whichever way you walk there is one about a minute from the start and another every minute after (in the Darkwood and the Bloomvale; the other three maps place theirs as told below). Walk up its steps and the night's clock stops: dawn comes no closer, the horde neither grows nor follows, and Ranked doesn't count the time. Down there each hero has their own weapon alone (the Knight his sword, the Ranger her bow, the Sorcerer his fireball, the Shadow his Shadow Blade, the Necromancer his Raise Dead, not his Miasma, or what it evolved into), and it fires only when you strike (X or Shift): at the nearest foe in its reach, the blade landing or the shot leaving on the sprite's blow frame; held, it strikes each time the weapon is ready. The others wait outside. Inside, about ten rooms hold sleeping packs of the night's foes (as strong as the minute you went in), and two to four named lords sleep in rooms of their own, each in the middle of a smaller pack, its guard, that wakes with it: two lords in the night's first five minutes, three from minute 5, four from minute 10, and one more (four at most) in a crypt three rings or more from the start (`cryptLords` in `public/js/game/dungeon.js`). One sleeps in the room the longest walk from the stairs, the others as far from the stairs and from one another as the crypt allows. The stairs you came down always lead back up: walk up them whenever you like, its lords alive or not. Each lord drops coins and gold and, rolled for each lord alike, a piece of **gear** and a champion's chest (half the time), the gear alone (a quarter) or the chest alone (a quarter), side by side, nothing of it in a wall (`LORD_DROPS` in `public/js/shared/items.js`). When the last one falls the wall breaks open on a way up at least five tiles' walk from you (the nearest such stretch of wall): moonlight runs along the shortest walk there (A*, worked out again as you move), on the map too. However you leave, up the stairs, through the hole, or by falling, which wakes you by the door outside, the crypt is sealed for the rest of the run, and it counts as cleared only once its last lord has fallen. Whatever lies about when you climb out (gems, gold, chests, gear) comes with you. Each chamber has a row or two of boxes along its walls (2 to 10), not the many of a Dungeon Run floor.

**The Survival maps** (`public/js/data/maps.js`) open in turn, the Sunscorch, the Frostfell, the Bloomvale, the Darkwood and the Abyss, a night won on one, on any difficulty, opening the next (the unlock ladder, below). The owner's, 28 October 2026: "the first one where we start is the desert map. From there on, we progress to the frozen map. From there on, we progress to our current forest map. And from there on, we progress to the demonic map". He asked for a "bright flower, colorful map" too but didn't place it: it comes between the frozen map and the forest, the bright maps before the dark ones (the designer's call). While Survival is the trial chosen, a row of tabs under the trials picks the map (DESERT, FROZEN, MEADOW, FOREST, HELL): moving along it picks the one in focus, a shut one wears a padlock and says what opens it, and the map picked is remembered with the settings. Survival's card then shows the map's picture and name, the screen behind it its land, and its name opens the night and heads the results. Each map is the Darkwood's night on other ground: the same clock, waves, swarms, rings, packs and last stand, three bosses at the same times (4:30, 9:00 and 13:00, never one twice), and a horde of its own, kind for kind in the Darkwood's places of the night. Its land (its roads, shrines, crypts, groves and landmarks, on the Darkwood's crossroads or on ground of its own) is laid out from a seed of its own and dressed in a look of its own (`public/js/game/biomes.js`, each map's in `public/js/game/biomes/`): its ground, what stands in each of the Darkwood's places, its night's light, fog, air and weather, and its crypts' look and names. All five play the Darkwood's music for now. Two are spent by day: the owner's, the same day, "we will have to only have to spend the night in the forest, make the desert and snow one be normal bright". The Sunscorch and the Frostfell stand in the sun for their whole fifteen minutes (a look's `sun`: a constant light, too bright for the monsters' lifted night edge), on their ground by day, under their weather all the same; their nights open "Survive 15 minutes", end "The horde breaks!" (a boss still standing flees the field) and their results say VICTORY. The Bloomvale, the Darkwood and the Abyss keep their nights and their dawns.

They grow harder in that order (the owner's, 28 October 2026: "they should be like that in terms of difficulty too ... do not alter their health by too much"): by who comes and when, and by four factors on the Darkwood's own numbers (a map's `foe`): its **horde**, how many come (the steady horde and every swarm, ring and pack, after the difficulty's bend, as a Nightmare's more is); **damage**, every blow the hero takes, before his armor; **health**, every monster's (champions, the crypts' packs and lords, the thief, the bosses and their summons too), never moved by more than 15%; and the horde's **experience**, more where fewer come, so a hero levels at about the same pace on every map.

It runs east and west without end (`public/js/game/topology/corridor.js`; the owner's, 28 October 2026: "long left to right map that has a mountain range at top and bottom"): a band of open sand about 1,200 px from range to range, the start in its middle, and above and below it ranges of terraced red sandstone, spires on their ridges and a cliff face under the top one, that the hero can't climb; the horde crosses them, at 0.8 of its pace while on the rock as the Dungeon Run's horde crosses its walls, fliers at full. **The Bloomvale's fae court** (`public/js/game/fae-rings.js`, `public/js/game/fae.js`). The owner's, 28 October 2026: "Meadow, IDK what to do with meadow, you guys figure out something, have some good game design idea how to make meadow not be identical to forest." Its land is the Darkwood's, but its horde does not always come at the hero: fae rings, circles of ten moonblooms 96 px across, stand all over it (about one every 720 px, where the land leaves room: off the start, the crossroads, the landmarks, the roads and the footpaths, nothing standing in the 64 px clearing at a ring's heart), and each wakes on a clock of its own, about once a minute. It **stirs** for 6 s, its blooms opening one by one, clockwise like a clock filling; then it **dances** for 12 s, and every monster of the horde that crosses its line is swept into a wheel turning round it, charmed pink, no longer chasing the hero but still biting him if he touches one (a Thorn Witch in the wheel never shoots). He leads the horde in, stands in the clear **eye** and cuts the wheel down: the eye is as safe as he is strong, closing in seconds on Veteran and Elite unless he kills as fast as they come. Its last 3 s are the **quickening**: the blooms blink, the line turns red-violet, the wheel speeds up and a bell rings; when the music stops the dancers **break wild**, the burn's tint flickering on them, at up to 1.25× their pace for 3 s and never faster than the swift (a bare Knight's pace), never to be taken again. No boss, crypt lord, champion or thief ever dances. From 8:00 the court turns **Unseelie** ("The Unseelie Hour"): violet rings, 10 s dances and 4 s wild releases at up to 1.4×. No dance begins before 1:40 or after 13:40, so the last stand and the dawn are left alone. The first ring that wakes near the hero raises "A fae ring stirs", and the HUD's arrow points to the nearest ring awake. To pay for the help, a little more of the horde comes for a little less experience each (×0.95 and ×1.05).

**The Darkwood**: the night as it always was, number for number and draw for draw: its oak meadows, pinewoods and cursed woods, rain with thunder or a clear sky, its crypts the Crypts, Barrows, Tombs, Ossuaries, Sepulchres and Vaults, a third of them Undercrofts. A Survival run that names no map (the tests, the bots, the tools) is spent here, and Ranked and the Dungeon Run keep to it.

**The Abyss**: "Ash, fire and the legions of the pit. The hardest night of all." Islands of dead land over a gulf (`public/js/game/topology/islands.js`; the owner's, 28 October 2026: "patches of land connected by bridges and occasionally just land"), one about every 900 px, the start's the largest, each joined to three or four of its neighbours by a bridge of planks, bone or stone, a thin isthmus or a broad joining of land, so every island can be walked to from every other. Below them, one or the other by the run's seed: **lava**, molten round every island and under every bridge, glowing and lighting their edges, or **the void**, cliffs dropping into darkness, faint debris falling past them. The hero can't step off the land or a bridge; the horde crosses the gaps, at 0.8 of its pace over them, fliers at full. On the islands: ash where the Darkwood has its oak meadows, black basalt for its pinewoods, blood-red fields for its cursed woods, scorched causeways from each island's middle out to its joinings, and the ground cracked, the cracks glowing and lighting the night where they run. A shrine stands on every other island, a crypt on some of the rest (one a step from the start, four more a minute's walk away), graveyards, gallows, stone circles and ruins on others. Charred trees with embers in their bark stand in the oaks' places, obsidian spires in the pines', black thorns in the dead trees'; brimstone vents breathe fire where the mushrooms glow, braziers burn for the lanterns, the stone circles cast a blood-red light, embers rise and ash falls. Its weather: clear, ashfall, now and then an ember storm, embers whirling up through the ash and red lightning with the Darkwood's thunder. Drawn new: Flameskulls (bats), Fiendlings (Goblins, coming in threes as they do), Horned Brutes (Orc Brutes) and Magma Golems (Ogres); recoloured: Cinder Rats, Magma Slimes and Slimelets, the Damned (Ghouls) and Tormented Souls (Wraiths); kept: Skeletons, Hellhounds, Widow Spiders, Cultists, Imps and Death Knights. Its pockets from 3:00 are the Darkwood's from 4:00 (Hellhounds in the Dire Wolves' place), and its last minute and a half brings a little more of its toughest. Its crypts are hellgates lit by fire, the Inferno inside: Pits and Abyss Gates.

How light each map is (the luminance of its ambient light, white being 1): the Sunscorch and the Frostfell about 0.97 and 0.96 all day, and at their nights' deepest the Bloomvale 0.73, the Darkwood 0.45 and the Abyss 0.33, where what is seen is mostly what glows. (The Sunscorch's and the Frostfell's moonlit grounds and nights are kept in their looks, `ground` and `night`, for a night they may be given again.) Each map's weather is forecast from the run's seed as the Darkwood's is (`public/js/game/weather.js`), its first two minutes clear and its sky clearing before the end (the Frostfell's opening and ending in falling snow instead), and but for the Sunscorch's duststorm and the Frostfell's gusts (`public/js/game/hazards/`) it is all for the eye and the ear. Only rain is heard and only rain wets a step; snow, sand, ash and petals fall silent, and lightning brings the same thunder anywhere.

**The four new bosses** each fight with a night boss's attacks at his numbers (`kit` in `public/js/data/enemies.js`, `BOSS_AI` in `public/js/game/bosses.js`), each with its own shot, summons, blast, words and colours where the kit has them, and stand as tall as the Butcher and the Lich. **Neferkhet** fights as the Bone King: his slam is a holy blast that throws a ring of firebolts where the King's throws bones, he calls up Mummies, and under half his health he throws fans of five firebolts too. **Hrimgar** fights as the Butcher: a warned charge that throws up snow and a blast of frost round him, faster once enraged under 30% of his health. **Sylvaine** fights as the Lich: rings of thorns that fly through walls as his skulls do (the Thorn Witch's thorn breaks on them, as the Cultist's bolt does), three homing thorns with each ring under half her health, a blink away in petals, and Pixies called up. **Belzakor** fights as the Bone King too, his slam a fire blast, his rings and fans firebolts, his summons Fiendlings. A Darkwood boss on another map calls up that map's kind in place of his own: the Lich's Wraiths rise as Dust Wraiths in the Sunscorch and as Frost Wisps in the Frostfell, the Bone King's Skeletons as Myconids in the Bloomvale.

The horde walks in **four classes of speed** (`hordePace` in `public/js/game/enemies.js`), the same on every difficulty: swift (bats, rats, imps, Hellhounds) at a Knight's own pace with no upgrades, 74.7 px/s; quick (Dire Wolves, spiders, Goblins, slimelets) a tenth slower; steady (Skeletons, Wraiths, Death Knights, slimes) two tenths; slow (Ghouls, Ogres, Orc Brutes, Cultists a tenth slower still) three tenths. The other maps' kinds each walk in the class of the Darkwood kind they stand for (a Carrion Scarab as a rat, a Yeti as an Orc Brute, a Frost Witch as a Cultist, a tenth slower still; `STANDS_FOR` in `public/js/data/enemies.js`). Bosses, crypt lords and the Gilded Thief keep their own.

There are **three difficulties**, chosen on the trial screen and remembered with the settings (`public/js/data/difficulty.js`). On 23 October 2026 Veteran was renamed Elite, Normal Veteran, and a new, easier Normal came in under them; a new player starts on Normal.
- **Elite:** the old Hard, with about 3.9× as many monsters (four times the 45% more it had, 20 October 2026, then two thirds of that, 21 October) that each have about 2.3× the health and deal about 2.8× the damage. It pays gold at the old Hard rate (×1.5).
- **Veteran:** Elite with every monster at 70% less health (champions, bosses and the crypts' lords too), and every blow the hero takes halved, after his armor, from monsters, their shots and the bosses alike. A third as many of the monsters that shoot or lunge come (Cultists, Dire Wolves, Orc Brutes, Hellhounds), in the steady horde, the packs and the crypts; other kinds take their place. Its horde is half Elite's (a third of what both sent before, 21 October 2026), in the steady horde and the swarms, rings and packs alike. For the last six minutes of the night, from 9:00, 30% more of the same monsters come, in the steady horde and the swarms, rings and packs alike; on a Dungeon Run, whose floors' clocks map onto the same night, from about 3½ minutes into the second floor and all through the third, and on the first too for anyone who lingers there about 11 minutes. It pays gold at the old Medium rate (×1).
- **Normal:** Veteran with an eighth of its horde (the steady horde and the timed swarms, rings and packs; champions, bosses, the thief and the crypts' packs as ever), the hero and every monster walking 30% slower, and the monsters 10% slower again; the clock keeps real time. It pays gold at the old Easy rate (×0.75).

Ranked is always Elite, since it keeps one best time per hero. A night survived on any of them counts on the unlock ladder.

**Nightmare** is a box under Elite, ticked or not on the trial screen and remembered with the settings like the difficulty (off at first). An Elite modifier (its box is shut on Normal and Veteran), it sends three times as many monsters (twice before 21 October 2026), each class of the horde walking about 21% faster (the swiftest 5% past a Knight with every rank of Swiftness), in the steady horde and the timed swarms, rings and packs alike, in Survival and on a Dungeon Run; each monster is as strong as ever, and the crypts' sleeping packs, champions, thieves, bosses and their summons come as they would (`NIGHTMARE` in `public/js/data/difficulty.js`, `hordeMore` in `public/js/game/spawner.js`). No more than 900 monsters stand at once all the same, and how many stand depends on how fast the hero kills: a Nightmare's steady horde comes at three times Elite's rate (see the steady horde below), some 125 a second at 5:00 and 340 at 15:00, more than any hero cuts through, so it soon stands at the cap. Past 900 a new monster comes in the place of the farthest that stands well off the screen, which simply vanishes, never seen (no drops, no kill, no XP), so the horde the player sees keeps coming; see the cap below. It pays its gold ×1.5 on top of the difficulty's (×1.5 on Normal, ×2.25 on Veteran), kept modest (more monsters bring in a little more gold of their own: with the Knight on Normal the gem-collecting bot found 2047 gold in a Nightmare night against 1906); its victory bonus is the difficulty's, and a win counts as one on its difficulty. The HUD says NIGHTMARE beside the clock, and the results screen after the mode. Ranked keeps one best time per hero, so it is never a Nightmare: on its trial card the box isn't shown.

Monsters pass through props and through the trees, and ease apart from one another (`public/js/game/crowd.js`): a crowd spreads round the hero rather than piling onto one spot, though a press of them still squeezes together. They can't stand inside the hero, and those against him ease him off them, softly (never as fast as he walks, so he can always walk out; a boss or a lord never moves him). A crypt's walls stop them all but Wraiths, bats and imps. On a Dungeon Run floor the horde hunts the hero from anywhere, straight at him through walls, pillars and lava, a little slower while inside them (`WALL_PACE` in `public/js/game/enemies.js`); the walls still stop him. In a crypt a monster doesn't know where the hero is until it has seen him (ten tiles, as far as he sees, with no wall between) or been struck. Until then it strolls about, or sleeps with its pack; from then on it follows him round corners. What is sent at him (a ring, a swarm, a pack, a boss's summons), the bosses and the thief always know where he is.

**The steady horde comes at a rate**, never minding how many monsters stand (the owner's, 26 October 2026: "alive monsters are just alive and for the player to deal with and should not affect new monster generation"; before, it kept a number of them standing and sent more as the hero killed them). So many a second come in at the screen's edge, by the minute's pocket of `public/js/data/waves.js` (another map's own in `public/js/data/maps.js`): in the Darkwood, on Normal about 0.4 a second at dusk, 3.8 at 5:00, 13 at 10:00 and 23 at 15:00; on Veteran 3.2, 25, 65 and 97; on Elite 6.1, 42, 81 and 115. It grows through the night, gently over the first four minutes while the hero is weak, and bends late in the night so Veteran and Elite ask about what a strong hero can cut through rather than far past it; on the Endless Night it never stops growing (some 190 a second at 30:00, 340 at 60:00). A Nightmare triples it and each Cursed Skull adds a quarter, another map scales it by its horde (above), and a Dungeon Run floor sends a tenth fewer. Every 75 seconds from 0:45 a **wave** swells it for 15 seconds, up to 2½ times at its height. At the start of the night as many come at once as used to stand at dusk (12 on Normal, 96 on Veteran, 184 on Elite), on a Dungeon Run's later floors 8 seconds' worth. What the hero kills slowly piles up; one he leaves far behind (0.85 of the screen's width away across or down in the forest, more than 30 tiles' walk or out of reach on a Dungeon Run floor) simply vanishes, never seen (no drops, no kill, no XP), while what was sent at him is brought back to the screen's edge (`HORDE_RATE`, `hordeRate` in `public/js/data/waves.js`, `Spawner.rate`, `Game.relocate`).

**Swarms come in batches**: each of the night's swarms is a run of 2 to 5 (rolled each night), each three times the size it was, 7 seconds apart, and each told by its own warning about 2 seconds before it, saying which of the run it is ("2 of 4"). A swarm comes as a loose stream, 170 px across and up to 70 px deep (`SWARM_SPREAD`). On the Endless Night a swarm that comes back comes as a whole run too (`SWARM_BATCH`, `batchEvents` in `public/js/data/waves.js`).

**The cap**: no more than 900 monsters stand at once, props aside (boxes don't count, and still come at the cap). Past that, a new one comes only in the place of the one farthest from the hero, if it stands 0.6 of a screen diagonal off or more (413 world px on a 1080p screen: past every corner of the screen and past anywhere the horde comes in). It simply vanishes, never seen: it doesn't die, drops nothing and counts for no kill or XP. If none stands that far, the new one doesn't come, as before (the steady horde's due then is dropped, not saved up). The steady horde makes room for 20 a frame at most, so a burst can't churn it. What is sent at the hero (a ring, a swarm, a pack, a champion, the thief, a boss's summons) comes in full, each in the place of the farthest foe anywhere off the screen. Bosses, crypt lords, champions, the thief, a boss's summons and the crypts' sleeping packs are never the ones that make room (`HORDE_CAP` in `public/js/data/waves.js`, `Game.recycleFar`). The forest already lets the steady horde's stragglers go, and moves what was sent at the hero back to the screen's edge, once they are more than 0.85 of its width away across or down (`Forest.tooFar`, `Game.relocate`), so in the headless nights measured none ever stood a full diagonal off.

The clock keeps **real time**: the 15-minute night takes 15 minutes, and the 5:00 that brings in the next hero five. What runs faster is how the hero and the monsters walk: **about 52% faster** than they were drawn to on Veteran (`GAME_SPEED` in `public/js/data/difficulty.js`), on Veteran 20% less than that and on Normal 30% less again (`moveFor`), the monsters' speed classes kept in step with the hero's. The bots walk at the same speeds, so they play the game as people do.

### The unlock ladder

1. You start with the **Knight** and **15-minute Survival** in the Sunscorch only. The Knight has seven looks, chosen with **LOOK** under his panel on the hero screen and remembered with the settings: his own plumed knight, **Knight B** (a knight-errant in blued steel), the **Ember** knight (a living flame crest), the **Frost Warden** (winged helm, wolf-fur mantle), the **Black Knight** (horned, red-eyed), the **Thorn Knight** (antlers and a leaf blade) and the **Moon Knight** (a crescent crest and a starry cloak). Each was drawn with claude-pxl (MIT) by an artist subagent and refined by a reviewer (`gms/3001/sprites/lab/src/knight-<b..g>/`, baked by `tools/bake-heroes.mjs`).
2. Last **5 minutes** on the clock with a hero to unlock the next hero, free. A banner says so at 5:00, and the hero is yours when the run ends, whether you win, fall or quit.
3. Surviving the night with the **Necromancer** opens the **Dungeon**, for the Knight only at first.
4. **Beat the Dungeon** with a hero to bring the next hero into it.
5. Beat the Dungeon **with the Necromancer** to unlock **Ranked**, open to every hero.

**The maps** have a ladder of their own beside the heroes': the Sunscorch is open from the start, and a night won on a map, on any difficulty, opens the next: the Frostfell, then the Bloomvale, the Darkwood and the Abyss (`mapLadder` in `public/js/shared/progress.js`). The results announce it ("The Frostfell is open!"), a shut map's tab on the trial screen says what opens it ("Survive the night in the Sunscorch"), and the hero screen's Journey lists them in order. Everything else counts a night on any map alike: the next hero's five minutes, the wins and their stars (a night won with the Necromancer anywhere opens the Dungeon), the records and the milestones. A save from before the maps that has played spent all its nights in the Darkwood: it keeps the Darkwood and every map before it, and its nights won count as the Darkwood's, which opens the Abyss; the trial screen shows it the Darkwood until another map is picked. One that never played starts in the Sunscorch, as a new one does.

The hero screen always shows your next goal and each hero's longest run on the clock (in any mode); the next hero's card fills toward its five minutes with the hero before him, and stars mark what each hero has conquered (night survived, Dungeon beaten). The Codex's ultimates fill toward their 2:00 with each hero's longest run too.

The results screen stamps NEW BEST on every record a run beats (time, level, kills, bosses slain, gold found, the deepest Dungeon floor, a won Dungeon counting as Conquered), marks the weapon that dealt the most damage MVP, and counts the gold as a short cascade: the gold found, then a beat each for the difficulty's rate where it is above ×1 (Normal's ×0.75 is in the count from the start, never a step down), the wage and a win's bonus; any key, click or tap shows it all at once, and what is paid is the same. It announces anything a run unlocks, one by one, a page at a time when there are many (each page held a moment, then the next), and the first night won says the second circle's weapons are revealed. When the next goal is a time with the hero just played, its NEXT line shows the distance as a bar ("04:31 of 05:00 with the Knight · 29 s from the Ranger"). In a run, past 85% of the most kills a run has made a dim BEST stands beside the kill count, NEW BEST once beaten (never in the first minute). The Codex marks with a green dot what has opened since this browser last looked (its tabs and the title's CODEX too), and the title's UPGRADES shows a coin while the gold in hand buys a rank. These marks are presentation only: no timer, streak or odds goes with them.

There is no kill-streak counter on the screen. The owner's, 28 October 2026: "the combo counter on the right actually doesn't make sense, since apart from the very early game, the monsters just keep on spawning so quick that it just keeps on rising. Let us make sure to nicely flash damage numbers instead", and "the damage should be shown when its dealt, not just when monster dies ... not shown when deal on hero". The streak is still counted and its longest kept in the save (`best.combo`), but its count, its named tiers, their stings and its results row are gone (`COMBO` in `public/js/game/game.js`). Instead every damage number flashes white as it pops, and again as a quick second hit on the same foe adds into it (steady with **FLASHES: SOFT**; crits flash through their jackpot colours as before). Up to 40 plain hits and 20 crits on the horde show at once, 80 numbers in all (12, 10 and 40 before), so a blow that doesn't kill is seen too in a thick night, and only a hit landing on the hero's own body (`CLEAR`, 10 px round his middle, 22 before) is left unshown. The hero's own wounds show no number: the red flash, the shake and his bar tell them (`public/js/game/numbers.js`).

### Things to find

- **Soul gems** (XP) from every monster, and now and then a coin or a **fury orb** (rarer the faster you kill, but never gone), nothing more (champions, Gilded Thieves, crypt lords and bosses leave more); **gold**, **potions** and **elixirs** in what you break
- **Scroll of Gathering** pulls in every gem; the **Holy Relic** purges the screen and the **Frost Rune** freezes it (bosses, crypt lords and champions only take a heavy blow or slow down). All three lie only in what you break. **Fury orbs** charge your ultimate; they lie in what you break too
- **Champions** with randomly generated names and affixes, and **Gilded Thieves** that flee with treasure: 92 gold before greed and, one time in two, a chest (its icon stands over the thief's bar, and its banner says so as it comes). A thief is gone after 20 s, a sliver under its bar running down (red for the last 5), and its escape says what got away ("92 gold and a chest got away")
- **Treasure chests** from champions, bosses and three crypt lords in four. A max-level weapon plus its paired relic **evolves** when you open a chest; the rest of a chest is upgrades drawn like level-up cards (above), and gold. Luck makes a champion's or a boss's chest hold more, never a crypt lord's
- **Gear** from three crypt lords in four, every lord rolled alike (so up to four pieces a crypt): helm, armor, gloves, boots, amulet and ring, each Common (1 stat), Uncommon (2), Rare (3), Epic (3, stronger) or Legendary (4 and a power: +1 projectile, +40% crit damage, a revive, or +20% health and +2 armor; each power counts once, however many pieces worn carry it). Later in the night and farther from the start the odds get better, and nothing else changes them: **luck plays no part in what a crypt's lords leave**, not the gear's rarity, nor whether a lord leaves gear, a chest or both, nor what its chest holds, nor its gold; that is plain chance (`test/crypts.test.js`). Picking a piece up shows it beside everything worn, with what it would change; wear it (the piece it replaces is sold) or sell it, and sell anything worn while you're there. **Each hero keeps their own gear from run to run**; heroes don't share it (`public/js/shared/items.js`)
- **Shrines** of Fury, Haste, Fortune, Wisdom and Protection
- **Power-ups**, only in what you break (never dropped by the horde), luck making them likelier: a **Wild Mushroom** (10 s of double damage and 30% more speed), a **Ward Bubble** (5 s untouchable), a **Mirror Shard** (10 s of +1 projectile for every weapon), each 1 in 100; a **Treasure Map** (a chest a screen or so away, which the edge arrow points to; in a dungeon or crypt, a pile of gold) and a **Cursed Skull** (touch it and the rest of the run brings 25% more monsters and 50% more gold, up to three), each 1 in 200 (`POWER_UPS`, `PROP_LOOT` in `public/js/game/game.js`)
- Breakable barrels, crates, urns and lanterns, 2 to 5 to a site: in the forest a site every 5 to 9 seconds ahead of you (about 45 props standing at most), in a dungeon or crypt one row along a wall of each room, about three boxes a chamber (`PROP_SITES` in `public/js/data/waves.js`). The hero's weapons break them, and so do the Necromancer's skeletons and death knights: a blow one strikes at a foe breaks any box in its swing as well. They never go for a box instead of a monster, and walk through one as through anything but a wall (`Minion.attack` in `public/js/game/minions.js`). Half of them hold nothing; each of the rest holds one thing, which pops out a moment after the box breaks, hops about two steps to the side of the way the hero walks and waits there to be walked over (the pickup magnet leaves it be; `PROP_DROP`, `PROP_HOLD`): a third of them a potion, a third a fury orb, a tenth a Scroll of Gathering, and the rest gold, now and then an elixir or a Frost Rune and, half as often, a Holy Relic (`PROP_LOOT` in `public/js/game/game.js`). Luck makes the scrolls, elixirs, runes and relics likelier. A rare find pops out with a chime in a short beam of its own light, and the rarest (an elixir, a Holy Relic, a Treasure Map or a Cursed Skull) with a stronger sting and its name over where it lands (`BOX_FIND`).

### Weapons and evolutions

Each hero has a **signature weapon** no other hero can find (the Necromancer has two, and starts with both); every other weapon is **shared by all**, offered to any hero on his level-ups. Relics are shared by all too. A weapon at level 8 with its relic evolves when a chest is opened, into something better than it in every way (`test/signature-weapons.test.js` checks every stat). One relic is unlike the rest: the **Phoenix Heart** (bought once in the Armory for 1,500 gold, for sale once the Knight has evolved his Longsword, and then found by every hero; +1 revive, and while it is held **any** weapon at level 8 evolves at a chest, its own relic or not) is offered only once the hero's own signature weapon has evolved; when he falls it is the revive spent first and it is gone (a Second Wind from the Armory or a legendary waits for the next fall), its relic slot free, and it can be offered again 5 levels later. Each time it can be offered it is on the next two level-ups for certain (a reroll keeps it among the new cards), and after that only by chance; a chest draws it only by chance (`test/phoenix.test.js`). Each hero's `unique` and `start` are in `public/js/data/heroes.js` (with `SHARED_WEAPONS` and `weaponsFor`), the weapons in `public/js/data/weapons.js`. ## Saving: everything lives in cookies

The server keeps **no database**. The only thing it writes to disk is its cookie key (`.data/cookie-secret`, or set `COOKIE_SECRET`).

| Cookie | Holds | Set by |
| --- | --- | --- |
| `fs_profile` | gold, wins per mode and difficulty (Normal counts as the old Easy, Veteran as the old Medium, Elite as Hard), records, Armory ranks, unlocked heroes, each hero's achievements (night survived, Dungeon beaten), Ranked personal bests, each hero's longest run, the gear each hero wears, the Survival maps open and, for each, the difficulties a night has been won on | server, encrypted (AES-256-GCM), HttpOnly |
| `fs_settings` | volume, screen shake, damage numbers, CRT, FPS, and the difficulty, Nightmare box and Survival map last chosen | browser (localStorage where it can, else a cookie) |
| `fs_seen` | what this browser has been shown, for the NEW marks: the Codex entries looked at, and the milestones' weapons and relics a level-up has offered | browser (localStorage only; without it no NEW marks) |

There is no cookie for a run: nothing of a run is saved while it lasts, only its results when it ends (above). A run cookie left by an older version of the game (`fs_run`, or `fs_lrun` / `fs_drun` with static hosting) is deleted when the game loads.

The profile cookie is a few hundred bytes, and at its largest (every hero in six legendaries, every Survival map open and won on every difficulty, every record at its most) about 3,200 characters encoded. The most the game reads back (`MAX_STATE` in `public/js/shared/profile.js`, 4,000) is kept a quarter above that (`test/profile.test.js` measures it), which leaves about two characters: a new field needs room made first. So it packs what it can: the heroes as one number, a bit each; each hero's gear as a few numbers per piece; the heroes' Ranked bests and longest runs as base-36 numbers, a string each; and, since 28 October 2026, the Survival maps as two numbers, `mo` (a bit for each map open) and `mw` (three for each map, one for each difficulty a night has been won there on, a Nightmare's counting as Elite's). The heroes' marks (`feats`, their stars) are read back packed that way too, but still written as an object, as every older build reads them: one still open in a tab, or put back, would read a packed string as no marks at all and write the save back without them, the Dungeon and Ranked shut and every star gone. Such a write now loses only `mo` and `mw`, and the maps open again as for a save from before them. The server keeps a run's gear only if every piece is one the rules could have rolled, and no more of it is new than the run found: a piece at most from each crypt lord it slew, and so at most four for every crypt it could have reached (`MAX_LORDS` in `public/js/shared/items.js`). It is encrypted with a key derived from the server secret, so players can neither read nor edit it, and bound to its cookie name so no other cookie (a developer session) can stand in for it. Cookies written before encryption (signed, readable JSON) are accepted once and re-issued encrypted.

If the save exists but can't be decrypted (damaged, tampered with, or written under a different server key), the game says so on the title screen and offers a fresh start. The old cookie is left untouched until the player accepts, so restoring the right key brings it back.

**When deploying, set `COOKIE_SECRET` to a long random value and keep it stable.** If the key changes, for example because `.data/` isn't persisted between deploys, every existing save becomes unreadable at once.

Run reports are clamped server-side: gold is capped by run length (at most two hours for the 15-minute night with its crypts), gear by how many crypt lords the run could have reached (four to a crypt, a crypt every 45 seconds of its time and the one by the start), a victory only counts if the run lasted long enough to be one, a run that doesn't name its difficulty is paid as Veteran, one that doesn't say it was a Nightmare (or says so in Ranked) is paid as none, and a run in a mode the hero hasn't unlocked yet is refused. A night names the Survival map it was spent on: one in the Abyss, which sends a fifth more monsters, may slay and pick up a fifth more, but only on a save with the Abyss open; one on a map the save hasn't opened, or naming none (an older client, the bots), is never refused for it: it is paid and counted as ever, but marks no map. The game runs in the browser, though, so these are bounds, not proof: the cookies can't be forged, but a hand-made run report within the bounds is still paid. The unlock ladder lives in `public/js/shared/profile.js`, shared by the server and the browser.

If the game is served as plain static files (no `/api`), it keeps the save in the browser's localStorage with the same rules (`fs_lprofile`; a cookie only where localStorage can't be used, and a cookie save of before moves across the first time it is read: `saveBox` in `public/js/engine/storage.js`), as the itch.io release must, framed by another site whose cookies browsers block (they can't be meaningfully encrypted without a server, since the key would ship in the page). An unreadable one gets the same fresh-start prompt. A game server that is there but not answering (no connection, or a 5xx) is not mistaken for static hosting: the title screen says it can't be reached and offers to try again. A run the server doesn't take is never faked either: the results screen says its gold isn't saved and offers to save again.

### API

| Method | Path | Body | Effect |
| --- | --- | --- | --- |
| GET | `/api/state` | — | the profile, plus `unreadable: { profile: true }` when the save can't be decrypted; deletes a run cookie left from an older version |
| POST | `/api/run` | `{ mode, map, diff, nightmare, hero, victory, time, gold, kills, level, floor }` | a run has ended: pay out gold, record wins, achievements and Ranked bests; the reward lists anything newly unlocked |
| POST | `/api/buy` | `{ id }` | buy an Armory rank |
| POST | `/api/refund` | — | refund all Armory ranks |
| POST | `/api/reset` | — | wipe progress |
| GET | `/api/dev` | — | developer mode status: `{ enabled, open, authed }` |
| POST | `/api/dev/login` | `{ key }` | start a 12-hour developer session (with `DEV_KEY`) |
| POST | `/api/dev/logout` | — | end the developer session |
| POST | `/api/dev/profile` | `{ profile }` | replace the whole profile (developer session only; still sanitized) |

POSTs must be `application/json`, and a JSON object (anything else is a 400). Any other path under `/api/` is a 404. Cookies are `SameSite=Lax`, and `Secure` behind HTTPS (including `X-Forwarded-Proto`).

## Meta-progression (the Armory)

The menu groups permanent upgrades into Power, Survival and Preparation. Select a tile to inspect its current and next effect, then buy explicitly. Hero selection includes Gear, Abilities and a Journey overview, with a separate Play button. The Codex is one scrollable list of weapons, relics, ultimates and unlocks. Tiles show short effects or direct requirements; the full description of the tile in focus is in the panel under the grid, with a weapon's evolution recipe once a run has made that evolution (until then "Evolves at level 8 with a relic yet unknown", and the level-up cards and the pause screen keep its relic unknown too: the owner's, 27 October 2026; `evolutionRecipe` in `public/js/ui/menu-copy.js`). Weapon Exclusions open five slots at most, at 10, 500, 3,000, 10,000 and 30,000 kills counted as on Veteran (a Normal kill as eight, an Elite one as half, a Nightmare one as a sixth; `exclusionAt` in `public/js/shared/progress.js`). Each slot lets one shared weapon stay out of future runs; including it again frees the slot, and the last shared weapon a run would offer always stays in. Mystery weapons share one discovery card until revealed. Records has three tabs: OVERVIEW, HEROES (each hero's wins by mode and difficulty, and what his stars mean) and RANKED, all nine heroes' personal bests. Mouse hover previews modes and difficulties without changing them; keyboard and gamepad navigation still selects along each row.

Gold from runs buys permanent ranks: Might, Armor, Vitality, Recovery, Haste, Reach, Swiftness, Magnetism, Fortune, Wisdom, Greed, Insight (rerolls), Exile (banishes), Endurance (effect duration), Velocity (projectile speed), Echo (+1 projectile for every weapon) and Second Wind (up to two revives). Ranks can be refunded at any time. Each rank of Armor is a point of armor.

A point of **armor**, wherever it comes from (the Armory, the Knight's own two, the Plate Armor relic, gear), takes a tenth off what is left of each blow, or 1 damage if that is more. So every point adds a little less: one takes 10%, five 41%, ten 65%. All of it together never stops more than 95% of a blow, and a blow always does at least 1 (`armored` in `public/js/game/player.js`).

The 15-minute night was tuned, on what is now Elite, so a fresh profile can't win it and a full Armory can: with the Knight, the gem-collecting bot died in 33 of 35 seeded games without the Armory and won all 35 with every rank (`node tools/bots.mjs --bot=gems --runs=35 --armory=none` and `--armory=max`; add `--diff=veteran` for Veteran, `--diff=normal` for Normal). That was before armor took a tenth of a blow a point, which makes the Knight and any armored build sturdier, and before the levels' strength was doubled and the breakables tripled (16 October 2026): since then the same bot, without the Armory, has won 4 of 4 seeded nights with the Knight on what is now Elite (1 of 4 before), and on what is now Veteran, at 70% less monster health, 4 of 4 with the Knight and the Necromancer alike. A Nightmare (`--nightmare`) on what is now Veteran (it was allowed there then) didn't stop the Knight on seed 1: he won it too, with 51 735 kills against 34 191 and at level 134 against 108, the doubled horde's gems carrying him further. All of these runs came before the monsters' 20% more health and damage, the horde doubled twice, the slow monsters sped up and the 15% faster game (20 October 2026), which the bot has not measured since. What spawns when is a table of minute pockets in `public/js/data/waves.js`.

## Bot play-testing

Scripted bots play the real game in Node, with no browser or server: draw calls go to a dummy canvas and `Math.random` is seeded per game, so a seed always replays the same game, many times faster than real time. Compare strategies, heroes and modes over many runs:

```bash
npm run bots                                    # every strategy · Knight · 15-minute night · 3 runs
node tools/bots.mjs --bot=idle,circle,kite --hero=knight --mode=s15 --runs=10 --seed=1
node tools/bots.mjs --bot=kite:r=40,kite:r=60 --hero=all --max=10:00 --each
node tools/bots.mjs --bot=gems --pick=all --armory=max --json=tools/out/gems.json
node tools/bots.mjs --bot=gems --nightmare                # Elite, three times the monsters
node tools/bots.mjs --list                      # strategies, their parameters and the level-up policies
```

Every option takes a comma list (or `all`) and the report gets a row per combination; run *i* of every row plays seed *seed + i*, so rows compare like for like. Games step at a fixed 60 Hz (`--hz`), run on all cores but one (`--jobs`) and stop at `--max` game time (an hour by default). `--each` adds a line per game (build, damage by source, what killed it) and `--json=FILE` keeps every result. | --- | --- | --- |

None of the strategies aims, so a weapon that flies only where the hero faces (the Hunting Bow) fares badly with any of them: they walk away from foes, or stand.

### Writing a strategy

A strategy gets a read-only view of the game every tick and says where to walk; it may also choose level-up cards. Save one as a module and pass its path to `--bot`:

```js
// mybot.mjs:  node tools/bots.mjs --bot=./mybot.mjs:panic=40,gems
export default {
  about: 'Runs from anything within `panic`, else walks to the nearest gem',
  params: { panic: 30 },
  make({ panic }) { // once per game; keep any state in this closure
    return {
      tick(v) {
        const foe = v.nearest(panic);
        if (foe) return { x: -foe.dx, y: -foe.dy, ult: v.me.ultReady };
        const gem = v.pickups(300).find((p) => p.kind === 'gem');
        return gem ? { x: gem.dx, y: gem.dy } : { x: 0, y: 0 };
      },
      pick: (cards) => cards.findIndex((c) => c.type === 'weapon'), // -1 leaves it to --pick
    };
  },
};
```

`tick` returns `{ x, y, ult }`: a heading, whose length (capped at 1) is the share of full speed, and whether to press the ultimate. A bare `(v) => ({ x, y })` function works too. Positions are world pixels, `dx, dy` point from the hero to a thing and `d` is its distance; lists come nearest first.

| View | |
| --- | --- |
| `v.t`, `v.dt`, `v.phase`, `v.kills` | seconds survived, the step length, how far the night's enemy mix has advanced, kills |
| `v.me` | `x, y, hp, maxHp, hpFrac, level, fury, ultReady, speed, magnet, armor, weapons, passives` |
| `v.enemies(r)`, `v.nearest(r)`, `v.boss` | awake foes within `r` (`x, y, dx, dy, d, r, hp, type, boss, elite, dmg, speed, fly`); the boss being fought |
| `v.shots(r)`, `v.hazards(r)` | enemy missiles; telegraphed slams yet to land (`shape`, `r`, `left` seconds) |
| `v.pickups(r)` | gems and loot: `kind`, `value`, `pulled` (already flying in) |
| `v.world` | `dungeon`, `solid(x, y)`, `path(x, y)` (next step of the shortest walkable path), `stairs`, `guardian` |
| `v.rng()` | the bot's own seeded dice |

Level-up cards are `{ type: 'weapon' | 'passive' | 'bless' | 'haste' | 'reach' | 'heal' | 'gold', id, name, level, isNew }`, and `pick` returns the index of one. The built-ins live in `public/js/bots/strategies.js` and `picks.js`; one added there also works in the browser, where `__fs.sim(60, { bot: 'kite' })` lets you watch it play.
